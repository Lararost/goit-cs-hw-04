# goit-cs-hw-04

Домашня робота «Конкурентність та паралелізм».
Пошук ключових слів у текстових файлах двома способами:
`threading.Thread` та `multiprocessing.Process` із `multiprocessing.Queue`.

## Вимоги

Python 3.10 або новіший. Усі модулі входять у стандартну бібліотеку:
встановлювати пакети або Docker не потрібно.

## Швидкий запуск на Mac

Розпакувати папку goit-cs-hw-04 на Desktop та виконати:

```bash
cd "$HOME/Desktop/goit-cs-hw-04"
python3 main.py --output results.json
```

Програма обробить sample_texts, виведе словники та час обох реалізацій,
перевірить їхню рівність і збереже results.json.

Окремі версії:

```bash
python3 threading_search.py --workers 4
python3 multiprocessing_search.py --workers 4
```

Пошук у власній папці, включно з вкладеними папками:

```bash
python3 main.py --directory "/шлях/до/текстів" --keywords python docker "база даних" --workers 4 --output my_results.json
```

## Правила пошуку

- Вхідні файли: `.txt` (без урахування регістру розширення).
- Текст: UTF-8, також підтримується UTF-8 BOM.
- Пошук без урахування регістру через casefold(), включно з українською.
- Пошук підрядка: `python` також знайде `python3`. Це не пошук виключно
  цілих слів. Фрази дозволені; порожні ключові слова відхиляються.
- Ключі словника зберігають написання переданих ключових слів.
- Один файл входить у список слова лише один раз незалежно від кількості збігів.
- У словнику є також слова без збігів, їхні списки порожні.
- Шляхи відсортовані; відносні шляхи залишаються відносними.
- Файл читається повністю: максимальне споживання пам'яті залежить від
  розміру файлів, які одночасно обробляються. Для дуже великих файлів
  знадобився б пошук блоками з обробкою збігів на межах блоків.

## Реалізація

`common.py` розподіляє файли циклічно: кожен worker отримує власний список.
Файли не дублюються між workers. Кількість workers обмежена кількістю файлів.
Це розподіл за кількістю файлів, а не за розміром; при дуже різних розмірах
можливе нерівномірне завантаження.

`search_threading(files, keywords, workers=4)` повертає словник.
Кожен Thread записує локальний результат в окремий слот; об'єднання
відбувається в головному потоці після join(). Спільного змінюваного
словника, в який одночасно пишуть усі потоки, немає.

`search_multiprocessing(files, keywords, workers=4)` також повертає словник.
Кожен Process повертає локальний результат через Queue. Головний процес
читає чергу перед join(), щоб великий результат не блокував завершення
процесу. Обрано spawn для сумісності з macOS/Windows. Функція worker
визначена на рівні модуля; виконання захищене `if __name__ == '__main__'`.

Помилки файлової системи та декодування записуються в stderr; пошук
в інших файлах продовжується. Аварійне завершення дочірнього процесу
повідомляється окремо. Порожня папка дає словник порожніх списків.
Відсутня папка, некоректні аргументи або неможливість запису JSON
призводять до повідомлення і коду завершення 1.

## Порівняння часу

Використано time.perf_counter(). Вимірювання охоплює розподіл файлів,
створення workers, читання, пошук, передавання результатів та об'єднання.
Пошук файлів і запис JSON не входять у час кожної реалізації.

На маленьких файлах накладні витрати spawn та Queue можуть переважати
виграш від паралельності. У звичайній CPython зі GIL потоки можуть
перекривати файлове введення-виведення, але не гарантують прискорення
CPU-пошуку. Процеси мають власні інтерпретатори та можуть використати
кілька ядер. На час також впливають кеш ОС, диск та інші програми.
Це демонстрація двох підходів, а не гарантія прискорення. Для точнішого
порівняння потрібно багато запусків і більший набір текстів; порядок
запуску варто чергувати, бо друга версія може отримати прогрітий кеш.

## Перевірки

```bash
python3 -m unittest -v test_search.py
```

Тести запускають реальні потоки та spawn-процеси: регістр і Unicode,
BOM, фраза з переносом, відсутні збіги, дублікати, порожні файли та список,
1/3/20 workers, некоректний UTF-8, відсутній файл, папка замість файлу,
неправильні аргументи, великий результат Queue.

`results.json` — реальний приклад виконання під час підготовки в Linux.
Час на Mac буде іншим. Виконайте main.py, щоб замінити його власним результатом.
